# Техническая документация: модуль геометрии (`geometry.py`)

## Назначение

`geometry.py` — это **математическое ядро** всей системы. Модуль предоставлен организаторами хакатона и отвечает за:

- Валидацию входных сценариев формата `cosmo-A-1.0`
- Расчёт 3D-координат спутников в инерциальной и земной системах
- Определение доступных контактов (наземных и межспутниковых)
- Формирование полного «снимка» состояния сети на заданный момент времени

## Константы

```python
R     = 6371.0              # Радиус Земли, км
MU    = 398600.435507       # Гравитационный параметр, км³/с²
OMEGA = 2π / 86164.09054   # Угловая скорость вращения Земли, рад/с
```

| Константа | Значение | Источник |
|-----------|----------|----------|
| $R$ | 6371 км | Средний радиус Земли (сферическая модель) |
| $\mu$ | 398600.435507 км³/с² | Стандартный гравитационный параметр Земли |
| $T$ | 86164.09054 с | Звёздные сутки |

## Архитектура функций

```
load(path)           → dict           Чтение JSON + validate()
validate(scenario)   → None/raise     Проверка корректности всех полей
positions(s, t_s)    → (ids, xyz_inertial, xyz_fixed)
ground_position(g)   → ndarray[3]     Координаты наземного пункта
snapshot(s, t_s)     → dict           Полный снимок сети
sunlight(s, t_s, sun_eci) → dict      Теневая карта (цилиндрическая тень Земли)
```

## Подробное описание функций

### `validate(scenario) → None`

Выполняет 15 проверок корректности входных данных:

1. `schema_version == 'cosmo-A-1.0'`
2. Все числовые значения в `environment` конечны
3. Высота орбиты: $200 \leq h \leq 1200$ км
4. Наклонение: $0 < i \leq 180°$
5. `step_s` и `horizon_s` — целые положительные, `horizon_s % step_s == 0`
6. Угол возвышения: $0 \leq \varepsilon < 90°$
7. Дальность ISL: $0 < d \leq 10000$ км
8. Целевая доступность: $0 \leq a \leq 1$
9. ID плоскостей уникальны и непусты
10. Углы плоскостей: $0 \leq \text{raan/phase} < 360°$
11. ID спутников уникальны
12. `launch_stage ∈ {1, 2, 3}`
13. Ссылки `plane_id` разрешаются, `launch_batch ∈ {1, 2, 3}`
14. ID наземных пунктов уникальны и не пересекаются с ID спутников
15. Интервалы отказов валидны: $0 \leq \text{start} < \text{end} \leq \text{horizon}$

При ошибке выбрасывается `ValueError` с описанием проблемного поля.

### `positions(scenario, t_s) → (ids, xyz_inertial, xyz_earth_fixed)`

**Входные данные:**
- `scenario` — полный сценарий
- `t_s` — момент времени в секундах от начала расчёта

**Алгоритм:**

1. Вычисляем радиус орбиты: $r = R + h$
2. Вычисляем угловую скорость: $n = \sqrt{\mu / r^3}$
3. Для каждого спутника $k$:
   - Аргумент широты: $u_k = (\text{slot\_deg}_k + \text{phase\_deg}_k) \cdot \frac{\pi}{180} + n \cdot t$
   - RAAN: $\Omega_k = \text{raan\_deg}_k \cdot \frac{\pi}{180}$
4. Векторизованный расчёт координат (NumPy):

$$\mathbf{xyz} = r \cdot \begin{pmatrix} \cos\Omega \cdot \cos u - \sin\Omega \cdot \sin u \cdot \cos i \\ \sin\Omega \cdot \cos u + \cos\Omega \cdot \sin u \cdot \cos i \\ \sin u \cdot \sin i \end{pmatrix}$$

5. Переход к земной системе через матрицу поворота:

$$\mathbf{M}(\theta) = \begin{pmatrix} \cos\theta & -\sin\theta & 0 \\ \sin\theta & \cos\theta & 0 \\ 0 & 0 & 1 \end{pmatrix}$$

$$\mathbf{xyz}_{\text{fixed}} = \mathbf{xyz}_{\text{inertial}} \cdot \mathbf{M}$$

**Возвращает:** кортеж `(ids, xyz_inertial, xyz_earth_fixed)` — все массивы shape `(N_sats, 3)`.

### `snapshot(scenario, t_s) → dict`

Центральная функция — формирует полный снимок состояния сети.

**Алгоритм:**

1. Вычисляем позиции всех спутников (`positions()`).
2. Определяем **активных** спутников: `launch_batch ≤ launch_stage` И нет текущего failure.
3. **Межспутниковые связи (ISL):**
   - Для всех пар $(i, j)$ где $i < j$ (верхний треугольник):
     - $\delta = \mathbf{xyz}_j - \mathbf{xyz}_i$
     - $d = \|\delta\|$
     - Ближайшая точка к центру Земли: $\lambda = \text{clip}\left(-\frac{\mathbf{xyz}_i \cdot \delta}{\delta \cdot \delta}, 0, 1\right)$
     - $\text{closest} = \|\mathbf{xyz}_i + \lambda \cdot \delta\|$
     - Контакт доступен, если: $d < \text{isl\_range}$ **И** $\text{closest} > R$ **И** оба КА активны.
4. **Наземные связи:**
   - Для каждого наземного пункта $g$:
     - Координаты: $\mathbf{g} = R \cdot (\cos\varphi\cos\lambda,\ \cos\varphi\sin\lambda,\ \sin\varphi)$
     - Угол возвышения для каждого КА: $\varepsilon = \arcsin\left(\frac{(\mathbf{s} - \mathbf{g}) \cdot \hat{g}}{\|\mathbf{s} - \mathbf{g}\|}\right)$
     - Контакт доступен, если: $\varepsilon \geq \varepsilon_{\min}$ **И** КА активен **И** (для шлюза — нет outage).

**Возвращаемая структура:**

```json
{
    "t_s": 0,
    "satellites": [
        {"id": "S01", "x_km": 6769.76, "y_km": -1438.96, "z_km": 0.0, "active": true},
        ...
    ],
    "edges": [
        ["S01", "S02", 2700.44],
        ["G_MUR", "S04", 1705.88],
        ...
    ],
    "elevation_deg": {
        "G_MUR": {"S01": -34.59, "S04": 11.68, ...},
        "C65":   {"S19": 12.96, "S20": 21.10, ...},
        ...
    }
}
```

### `sunlight(scenario, t_s, sun_eci) → dict`

Определяет, находится ли каждый спутник на солнечной стороне или в тени Земли.

**Модель тени:** Цилиндрическая (Земля отбрасывает цилиндрическую тень вдоль направления «от Солнца»).

**Алгоритм:**

1. Нормализуем вектор Солнца: $\hat{s} = \frac{\mathbf{sun}}{|\mathbf{sun}|}$
2. Проекция позиции спутника на солнечный вектор: $p = \mathbf{xyz} \cdot \hat{s}$
3. Перпендикулярное расстояние: $d_\perp = \|\mathbf{xyz} - p \cdot \hat{s}\|$
4. Спутник в тени, если: $p < 0$ **И** $d_\perp < R$

## Вычислительная сложность

| Операция | Сложность | Для 48 КА |
|----------|-----------|-----------|
| Позиции | $O(N)$ | 48 операций |
| ISL рёбра | $O(N^2)$ | 1128 пар |
| Наземные связи | $O(N \cdot G)$ | 48 × 4 = 192 |
| Один snapshot | $O(N^2)$ | ~1400 операций |
| Полная симуляция | $O(T \cdot N^2)$ | 720 × 1400 ≈ 10⁶ |

Благодаря векторизации NumPy, один snapshot выполняется менее чем за 1 мс.
